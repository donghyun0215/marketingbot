# 설계 요약

## 시스템과 사람의 경계
사람이 개입하는 지점은 정확히 두 곳이다. 브리프가 요구한 그대로다.
1. **방향 결정** — 데이터가 추천한 주제를 채택/보류한다
2. **승인** — 생성된 결과물을 승인/반려한다 (반려 시 사유 필수)

그 외 전 구간(분석→추천→생성→검사→발행→귀속→브리핑)은 손이 가지 않는다.

## 닫힌 루프 (전체 구조)
```
성과+문의 → AI 분석 → 주제 추천 → [사람: 채택] → 생성(Voice Profile + 학습된 규칙)
   ↑                                                        ↓
   └── 발행(추적링크) ← [사람: 승인] ← Fact-Guard 검사 ←──────┘
              ↓                      ↓ (반려 사유·원문 그대로)
        승인글 → 코퍼스 편입     learned_constraints → 다음 생성에 주입
```
- 루프1: 발행 추적링크 → 문의 폼 ref → content_id 확정 귀속 (실배포 검증 완료)
- 루프2: 반려 사유 → 생성 규칙 (요약하지 않음 — 요약하면 판단 추적 불가)
- 루프3: 승인글 → 보이스 코퍼스 (쓸수록 목소리가 정확해짐)
- 루프4: 추천 id → 콘텐츠 → 성과·문의 체인 (집계 저장 없이 매번 체인 계산 — 항상 현재 사실)

## 8단계 커버리지 (정직 표기)
| 단계 | 상태 | 내용 |
|---|---|---|
| ① 아이디어 | **REAL** | 실데이터 이상치·수요 분석 → 근거 있는 주제 추천 |
| ② 기획 | **REAL** | 추천 채택 = 기획 확정, 근거·결정자·시각 기록 |
| ③ 원고 | **REAL** | Voice Engine (동일 모델 대조 실험 포함) |
| ④ 편집 | PARTIAL | 사실 검사·문체 검사 자동 / 이미지·썸네일 제외 |
| ⑤ 업로드 | PARTIAL | 자체 발행 + 추적링크 실제 / 외부 채널은 설계까지 |
| ⑥ SNS 확산 | DESIGN-ONLY | 채널 포맷 변환 설계 (API 승인 기간 사유 상동) |
| ⑦ 성과 취합 | **REAL** | 실데이터 임포트 + 자동 브리핑 |
| ⑧ 데이터 축적 | **REAL** | 4개 루프 전부 폐쇄 |

## 신뢰 요소 (왜 결과를 믿을 수 있는가)
- **승인 게이트:** 사람 결정 없이 published 불가. 중복 승인 차단(상태 조건부 전이)
- **판단 로그:** 모든 결정을 누가·언제·왜와 함께 audit_log에 기록 (actor: telegram:id / web)
- **추적성:** 추천 → 콘텐츠 → 발행 → 문의까지 id 체인. 규칙마다 출처 콘텐츠 연결
- **Fact-Guard:** 고객사명·가격·계약조건·대외비·출처미상 수치 스캔.
  실제 발행글 46편 오탐 차단 0건 검증. 고객사명은 차단이 아닌 확인 대상
  ("이 이름을 써도 되는가"는 사람의 판단)
- **오류 대응:** 텔레그램 장애 시 웹 대시보드 폴백 / 웹훅 secret 검증 + 승인자 화이트리스트 /
  429 백오프 재시도 / DB는 RLS로 공개키 접근 차단 / 고객사 실명 미저장(익명 별칭)
- **지표 자기검증 절차:** 채점 기준을 수정할 때마다 실제 코드프레소 글 46편이
  여전히 높은 점수를 받는지 검증. 통과 못 한 수정은 폐기 (볼드 신호 폐기 사례가 감사 로그에 있음)

## 알려진 한계 (숨기지 않는다)
- 문의 접수 엔드포인트는 데모용 공개 상태 — 프로덕션 전환 시 레이트 리밋·폼 검증 필요
- Voice Score는 "브랜드 문체 안/밖" 판별용. 자사 글 사이의 우열은 가리지 못함
- 직접 유입 문의는 여전히 출처 미상 (귀속은 콘텐츠발 문의에 한함)
- 승인 채널은 텔레그램이지만 게이트 로직은 채널 비종속 — 슬랙 전환은 표면 교체
