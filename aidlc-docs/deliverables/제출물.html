우리가 푸는 문제

우리는 여덟 단계가 전부 사람 손으로 돌아가고, 판단의 근거가 어디에도 쌓이지 않기 때문에 발생하는
성과의 원인 불명 · 발행 지연 · 매번 처음부터 시작되는 기획 문제를 해결합니다.

컨펌이 1~4일 걸리는 이유는 결재가 느려서가 아니라 매번 글 전체를 읽어야 하기 때문이고, 성과가 쌓이지 않는 이유는 데이터가 없어서가 아니라 되돌아오는 경로가 없기 때문입니다.

사실수치출처

수치는 코드프레소가 제공한 6개월 실데이터(2026.02~08)와 출제 브리프에서만 인용했으며, 고객사 실명은 저장하지 않았습니다.

이번에 풀지 않는 범위

  • 이미지·영상 편집 — 품질 판단이 시각 영역에 있어 기간 내 검증이 어렵습니다.
  • 뉴스레터·유튜브·PR 채널 — 채널 확장보다 한 흐름을 끝까지 닫는 것을 우선했습니다.
  • 외부 채널 실제 발행 — 링크드인 조직 페이지는 별도 API 승인이 필요해 발행 큐까지 구현했습니다. 제공받은 실데이터의 출처가 그 API이므로, 고객사는 이미 권한을 보유하고 있습니다.
  • AI 답변 인용(GEO) 측정 — 외부 데이터 소스가 필요해 다음 단계로 남겼습니다.

시스템이 도는 구간, 사람이 판단하는 지점

사람이 하는 일은 방향 결정과 승인 두 가지뿐이며, 두 지점 모두 텔레그램에서 처리됩니다.

성과·문의 ──▶ 분석 ──▶ 주제 추천 ──▶ ① 사람: 채택 ──▶ 생성(문체 + 학습된 규칙 + 실데이터) ▲ │ │ ▼ 문의 귀속 ◀── 발행(추적링크) ◀── 예약·즉시·행사연동 ◀── ② 사람: 승인 / 반려 ◀── 발행 전 검사 │ │ 승인글 ──▶ 보이스 코퍼스 반려 사유 ──▶ 생성 규칙

네 개의 되먹임

콘텐츠 → 문의발행 시 생성된 추적 링크로 유입된 문의가 해당 글에 귀속됩니다.
반려 → 생성반려 사유를 요약 없이 그대로 규칙으로 만들어 다음 생성에 적용합니다. 반려된 주제는 후보로 되돌아가 다시 시도할 수 있습니다.
승인글 → 코퍼스사람이 톤을 보증한 글이 학습 자료가 되어, 쓸수록 목소리가 정확해집니다.

결과를 믿을 수 있는 근거

승인 게이트

  • 사람의 결정 없이는 발행되지 않습니다.
  • 반려에는 사유 입력이 필수입니다.

판단 로그 · 추적성

  • 모든 결정이 누가·언제·왜와 함께 남고, 사람의 결정과 시스템의 실행이 구분됩니다.
  • 추천 → 콘텐츠 → 발행 → 문의가 식별자로 이어집니다.

발행 전 검사

  • 고객사명·가격·계약조건·출처 없는 수치를 표시합니다.
  • 고객사명은 차단하지 않고 확인 대상으로 올립니다 — 써도 되는지는 사람의 판단입니다.
  • 실제 발행글 46편 검증에서 잘못된 차단 0건입니다.

오류가 났을 때

  • 텔레그램 장애 시 대시보드에서 같은 처리를 합니다.
  • 생성 실패 시 주제를 후보로 되돌리고, 실패도 로그에 남깁니다.

알려진 한계

문체 점수는 브랜드 문체의 안팎을 가를 뿐 자사 글 사이의 우열은 가리지 못합니다. 직접 유입 문의는 여전히 출처가 남지 않습니다. 승인 채널로 텔레그램을 썼지만 게이트 로직은 채널에 종속되지 않아, 슬랙 전환은 표면 교체입니다.

채점 기준을 고칠 때마다 같은 관문을 통과시킵니다 — 수정한 기준으로 그 46편을 다시 채점해 여전히 높은 점수(중앙값 92점)가 나와야 채택하고, 그러지 못하면 폐기합니다. 실제로 네 차례 폐기·수정했고 기록은 저장소에 남아 있습니다. 저희 결과가 유리해지도록 맞춘 지표가 아니라, 고객사의 글로 검증한 지표라는 뜻입니다.

가장 크게 벌어진 축은 자사 근거(53 대 98)입니다. 일반 프롬프트 결과는 4배 이상 길지만 회사 이름이 한 번도 나오지 않습니다. 담당자가 말한 "어느 회사 블로그에 놔도 어색하지 않은 글"이 바로 이 상태입니다.

결론

범용 LLM은 회사의 사례를 모르고, 어제의 지적을 기억하지 못하며, 사람이 열어야 시작됩니다. 범용 LLM은 사람이 기억해서 써야 하는 도구이고, 이 시스템은 사람 대신 기억하는 구조입니다.

정직하게 덧붙이면, 생성물은 아직 블라인드 테스트를 통과하지 못합니다. 다만 그때 지적된 결함(문장마다 흔들리는 어미)을 지표로 만들어 전환률을 78.9%에서 0%로 낮췄습니다. 우리가 주장하는 것은 완벽한 생성이 아니라 지적이 규칙으로 쌓여 다음 결과가 나아지는 구조이며, 그래서 승인 게이트가 설계의 중심에 있습니다.
