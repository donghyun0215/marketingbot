우리가 푸는 문제

우리는 여덟 단계가 전부 사람 손으로 돌아가고, 판단의 근거가 어디에도 쌓이지 않기 때문에 발생하는
성과의 원인을 알 수 없고, 발행이 밀리고, 기획이 매번 처음부터 시작되는 문제를 해결한다.

병목의 재정의 — 컨펌이 1~4일 걸리는 이유는 결재가 느려서가 아니라 매번 글 전체를 읽어야 하기 때문이다. 성과가 쌓이지 않는 이유는 데이터가 없어서가 아니라 되돌아오는 경로가 없기 때문이다.

이번에 풀지 않는 범위

제외 항목사유

설계 요약

시스템이 도는 구간과 사람이 판단하는 지점

사람이 개입하는 두 곳

성과·문의 ──▶ 분석 ──▶ 주제 추천 ──▶ ①사람: 채택 ──▶ 생성(문체+학습된 규칙+실데이터) ▲ │ │ ▼ │ Fact-Guard 검사 │ │ │ ▼ 문의 귀속 ◀── 발행(추적링크) ◀── 예약·즉시·행사연동 ◀────────── ②사람: 승인 / 반려 │ │ 승인글 ──▶ 보이스 코퍼스 반려 사유 ──▶ 생성 규칙

사람이 하는 일은 방향을 정하는 것과 결과물을 승인하는 것 두 가지뿐이다. 나머지 구간은 손이 가지 않으며, 두 지점 모두 텔레그램에서 처리된다.

네 개의 되먹임

경로무엇이 돌아오는가
콘텐츠 → 문의발행 시 생성된 추적 링크로 유입된 문의가 해당 콘텐츠에 귀속된다
반려 → 생성반려 사유를 요약하지 않고 원문 그대로 규칙으로 만들어 다음 생성에 주입한다. 요약하면 무엇을 지시했는지 추적할 수 없다
승인글 → 코퍼스사람이 톤을 보증한 글이 학습 자료가 되어 쓸수록 목소리가 정확해진다
추천 → 성과추천·콘텐츠·성과를 식별자로 연결해 적중률을 낸다. 집계값을 저장하지 않아 항상 현재 사실이다

여덟 단계 커버리지

단계구현내용
① 아이디어실제 구현이상치·검색 수요 분석 후 근거를 붙여 주제 추천
② 기획실제 구현채택이 곧 기획 확정. 근거·결정자·시각이 기록된다
③ 원고실제 구현문체·학습된 규칙·실데이터 근거를 주입해 생성
④ 편집부분사실 검사와 문체 검사는 자동. 이미지·썸네일은 제외
⑤ 업로드부분자체 발행·추적 링크는 실제 동작. 외부 채널은 큐까지
⑥ SNS 확산설계채널별 포맷 변환 설계. 사유는 앞장 참조
⑦ 성과 취합실제 구현실데이터 적재와 자동 브리핑
⑧ 데이터 축적실제 구현네 개의 되먹임 경로가 모두 연결됨

일주일 안에 증명 가치가 높은 순서로 골랐다.

결과를 믿을 수 있는 근거

승인 게이트

  • 사람의 결정 없이는 발행 상태로 넘어갈 수 없다
  • 이미 처리된 건은 다시 처리되지 않는다
  • 반려에는 사유 입력이 필수다

판단 로그 · 추적성

  • 모든 상태 전이가 누가·언제·무엇을 근거로 일어났는지 남는다
  • 사람의 결정과 시스템의 실행이 구분되어 표시된다
  • 추천 → 콘텐츠 → 발행 → 문의가 식별자로 이어진다
  • 규칙마다 그 규칙을 만든 콘텐츠가 연결된다

발행 전 검사

  • 고객사명·가격·계약조건·출처 없는 수치를 표시한다
  • 고객사명은 차단하지 않고 확인 대상으로만 올린다. 써도 되는지는 사람이 판단할 문제다
  • 실제 발행된 자사 글 46편에서 잘못된 차단 0건

오류가 났을 때

  • 텔레그램이 응답하지 않으면 대시보드에서 같은 처리를 한다
  • 생성이 실패하면 주제를 후보로 되돌려 다시 시도할 수 있다
  • 외부 API 한도는 재시도하고, 하루 한도면 즉시 원인을 알린다
  • 권한이 등록된 사람만 승인할 수 있다
  • 실패도 로그에 남긴다. 보이지 않는 실패는 신뢰의 근거가 되지 못한다

알려진 한계

문체 점수는 “브랜드 문체 안인가 밖인가”를 가르며 자사 글 사이의 우열은 가리지 못한다. 직접 유입 문의는 여전히 출처가 남지 않고, 귀속은 콘텐츠를 거친 문의에 한한다. 문의 접수 경로는 데모용으로 공개되어 있어 운영 전환 시 요청 제한과 검증이 필요하다. 승인 채널로 텔레그램을 썼으나 게이트 로직은 채널에 종속되지 않으며, 슬랙 전환은 표면 교체다.

왜 그냥 범용 LLM을 쓰지 않는가

같은 모델에 같은 주제를 넣었다. 모델을 바꾸지 않았으므로 차이의 원인은 파이프라인뿐이다.

바뀐 변수는 셋이다 — 코퍼스에서 추출한 문체 지시, 반려에서 학습한 규칙, 실데이터에서 온 근거. 모델을 다르게 했다면 “모델이 좋아서 아닌가”라는 반문에 답할 수 없다.

범용 LLM이 시스템
근거회사의 실적과 사례를 모르므로 일반론으로 채운다자사 성과 데이터에서 인용한다
기억어제 지적받은 내용을 기억하지 못한다반려 사유가 규칙으로 남아 다음 생성에 적용된다
시작사람이 열어야 시작된다데이터를 보고 먼저 제안하고 사람을 부른다

범용 LLM은 사람이 기억해서 써야 하는 도구이고, 이 시스템은 사람 대신 기억하는 구조다.

정직하게 덧붙이는 것

생성물이 사람이 쓴 글과 완전히 구분되지 않는 수준에는 아직 이르지 못했다. 실제로 자체 블라인드 테스트에서 세 차례 모두 식별됐고, 그때 지적된 근거—문체가 문장마다 흔들린다—는 측정 지표로 만들어 반영했다. 인접 문장 간 문체 전환률은 78.9%에서 0%로 내려갔다. 우리가 주장하는 것은 완벽한 생성이 아니라, 사람이 지적한 것이 규칙으로 쌓여 다음 결과가 나아지는 구조이며, 그래서 승인 게이트가 설계의 중심에 있다.
