# 데모 영상 촬영 대본 (1분 50초)
*실제 DB 상태 기준 — 2026-08-29*

## 0. 촬영 세팅 — 한 화면 좌우 분할

**텔레그램 데스크탑 앱을 쓴다.** 폰으로 찍는 것보다 낫다: 브라우저와 텔레그램을
한 화면에 나란히 두면 **"채택을 누르는 순간 오른쪽에 승인 요청이 도착하는 장면"**을
전환 컷 없이 한 프레임에 담을 수 있다. 자동화가 도는 것을 말이 아니라 화면으로 보여주는 셈이다.

```
┌─────────────────────────┬──────────────────┐
│  왼쪽 62%               │  오른쪽 38%      │
│  브라우저               │  텔레그램        │
│  marketingbot.vercel.app│  @MarketingPulse │
└─────────────────────────┴──────────────────┘
```

- 브라우저 확대 110%, 북마크바 숨김, 전체화면 아님(창 모드로 좌측 배치)
- 텔레그램 창은 좌우로 좁게. 이전 대화는 위로 스크롤해 두고 새 메시지만 보이게
- 화면 녹화는 전체 화면 1회 녹화. 편집에서 필요한 쪽을 확대(줌)한다

**촬영 전 체크**
- [ ] 텔레그램 데스크탑 알림 소리 켜기 (도착 순간이 들리면 편집이 쉬워진다)
- [ ] 브라우저 확대 110%, 북마크바 숨김
- [ ] 텔레그램 이전 대화 위로 스크롤
- [ ] **API 호출은 딱 1회** (컷 3의 채택 클릭). 재촬영 시 그 컷만 다시.
- [ ] 대시보드 새로고침해서 최신 UI(파이프라인 레일)가 보이는지 확인

**⚠️ 절대 주의**
- 반려는 **#3 "재직자 기술 역량 진단·관리..."** 로만 한다
- 승인은 **#4 "인재 채용 전략을 찾는 실무자를 위한 실행 가이드"** 로 한다
- #4를 반려하면 /compare 마지막 컷이 깨진다

## 1. 컷별 대본

### 컷 1 — 문제 (0:00 ~ 0:16) · **왼쪽 브라우저 · 상단**
**보여줄 것:** 페이지 최상단. **파이프라인 레일**이 먼저 보이게.
**마우스 동선:** 레일의 파란 점 두 개(주제 제안 / 승인 대기)를 훑고 → 지표의 "콘텐츠 귀속률"에 2초 → 아래 빨간 막대로 이동

> 레일에 파란 점이 찍힌 두 칸이 사람이 판단하는 지점이다. 이 한 줄이 설계 설명을 대신한다.

**자막**
> 코드프레소의 실제 6개월 데이터입니다.
> 진성 문의 10건 중 6건은 어떤 글에서 왔는지 아무도 모릅니다.
> 마케팅 목표가 리드인 회사에서, 리드의 출처를 모릅니다.

**화면에 실제로 보이는 숫자:** 블로그 클릭 457 / 링크드인 클릭 2,842 / 진성 문의 10건 / 귀속률 40% / 승인 대기 2건

---

### 컷 2 — 시스템의 제안 (0:16 ~ 0:30) · **왼쪽 브라우저 · "다음 주제 후보"로 스크롤**
**보여줄 것:** 패널로 스크롤 다운. 후보 2건이 보임.
**마우스 동선:** #3 후보의 **근거 문구**에 커서를 대고 천천히 읽을 시간을 줌

**화면 실제 텍스트 (읽기용)**
> "인재 관리 트렌드"를 찾는 실무자를 위한 실행 가이드
> *검색 노출 208회가 있으나 평균순위 23.2위로 클릭을 놓치고 있습니다.*

**자막**
> 시스템이 데이터로 주제를 제안합니다.
> 감이 아니라 근거입니다. 노출은 있는데 순위가 밀려 놓치고 있는 검색어입니다.

---

### 컷 3 — 채택 (0:30 ~ 0:44) · **왼쪽 클릭 → 오른쪽 도착을 한 프레임에** ⚠️API 1회
**동작:** `채택하고 초안 생성` 클릭 → "초안 생성 중…" → 완료 문구 등장
**핵심:** 이때 **오른쪽 텔레그램에 메시지가 도착하는 것을 같은 프레임에 담는다.**
왼쪽 버튼과 오른쪽 알림이 한 화면에 있으면 "자동으로 넘어간다"는 말이 필요 없다.

> Voice 96 (대조군 83) · 확인 0곳 · 텔레그램으로 승인 요청을 보냈습니다

**자막**
> 사람이 하는 일은 여기까지입니다. 채택.
> 그 다음 기획·작성·검사·전달은 손이 가지 않습니다.

---

### 컷 4 — 폰 도착 (0:44 ~ 1:02) · **오른쪽 텔레그램**
**보여줄 것:** 승인 요청 메시지 전체. 위에서 아래로 천천히 스크롤.
**멈출 지점:** `Voice Score 96 · 확인 필요 N곳` 줄에서 2초

**메시지 구성 (실제 화면)**
```
승인 요청 · 블로그
"인재 채용 전략"를 찾는 실무자를 위한 실행 가이드
Voice Score 96 · 확인 필요 없음
선정 근거: 검색 노출 221회 · 평균순위 20.6위
본문 앞부분 ...
[✅ 승인] [❌ 반려] [📄 전문 보기]
```

**자막**
> 경영진 폰에 도착합니다.
> 글 전체가 아니라 **확인할 지점만** 옵니다.
> 컨펌이 1~4일 걸린 이유는 결재가 느려서가 아니라, 매번 다 읽어야 했기 때문입니다.

---

### 컷 5 — 반려와 학습 (1:02 ~ 1:22) · **오른쪽 → 왼쪽**
**5-1 (오른쪽 텔레그램):** **#3 메시지**에서 `❌ 반려` 탭
→ 봇이 "반려 사유를 적어주세요" 답장 요청
→ 사유 입력: **`숫자를 앞에 세우지 말고 사례로 시작할 것`**
→ 전송 → `❌ #3 반려 — 다음 규칙으로 학습했습니다` 메시지 확인

**5-2 (왼쪽 대시보드):** 대시보드 새로고침 → **"시스템이 배운 규칙"** 패널로 스크롤
→ 방금 쓴 문장이 목록에 나타남 (기존 1건 + 새 1건 = 2건)

**자막**
> 반려하면 이유를 반드시 남깁니다.
> 그 문장은 요약되지 않고 그대로 규칙이 되어, 다음 생성부터 적용됩니다.
> 같은 지적을 두 번 하지 않습니다.

---

### 컷 6 — 승인과 발행 (1:22 ~ 1:36) · **오른쪽 텔레그램**
**동작 순서**
1. **#4 메시지**에서 `✅ 승인` 탭
2. 새 메시지 등장: 발행 옵션 3개 → 프레임에 담기
   ```
   ✅ #4 승인 완료
   언제 내보낼까요?
   [🗓 9월 2일 (화) 10시에 예약]
   [🚀 즉시 발행]
   [📌 행사 연동]
   ```
3. `🚀 즉시 발행` 탭 → 추적 링크 메시지 수신

**자막**
> 승인 다음은 "언제 내보낼까"입니다.
> 캘린더 예약, 즉시 발행, 행사 일정 연동 중에 고릅니다.
> 발행하면 이 글만의 추적 링크가 생깁니다.

---

### 컷 7 — 귀속 (1:36 ~ 1:48) · **오른쪽 → 왼쪽**
**7-1:** 폰에서 방금 받은 추적 링크 탭 → 문의 폼 열림
→ 화면에 `유입 경로가 확인되었습니다 (c4-xxxxxx)` 문구가 보이는 것을 잡을 것
→ `문의 보내기` 탭
→ 폰에 `📩 문의 도착 — 귀속 확정` 알림 도착

**7-2 (왼쪽 대시보드):** 대시보드 새로고침 → **"콘텐츠가 문의를 만들었는가"** 패널
→ `과거 방식 40%` 옆 `이 시스템 발행분 100%` 대비를 보여줌

**자막**
> 이 링크를 거쳐 들어온 문의는 이 글에 귀속됩니다.
> 출처를 모르던 6건의 문제가 여기서 닫힙니다.

---

### 컷 8 — 왜 ChatGPT가 아닌가 (1:48 ~ 2:02) · **왼쪽 브라우저 `/compare` (전체화면으로 확대)**
**보여줄 것:** 상단 제목 → 좌우 본문 대비 → 아래 축별 표로 스크롤
**멈출 지점:** 표의 `자사 근거 53 vs 98` 행, 그리고 그 아래 문구

```
일반 프롬프트: 자사 언급 0회 · 고유 용어 0종
Voice Engine:  자사 언급 3회 · 고유 용어 4종
```

**자막**
> 같은 모델, 같은 주제입니다.
> 달라진 건 셋뿐입니다. 코퍼스에서 뽑은 문체, 반려에서 배운 규칙, 실데이터 근거.
> 왼쪽은 4배 길지만 회사 이름이 한 번도 나오지 않습니다.

---

### 컷 9 — 마무리 (2:02 ~ 2:10) · **오른쪽 텔레그램만 확대**
**보여줄 것:** 텔레그램 대화 전체를 위로 스크롤 — 브리핑 → 승인 요청 → 반려 → 승인 → 발행 → 문의 도착이 한 흐름으로 이어진 것

**자막**
> 주제를 고르는 것도, 초안을 승인하는 것도 모두 여기서 끝납니다.
> 데스크탑에서도, 폰에서도 같습니다.

## 2. 편집 지침
- 로딩·페이지 전환은 잘라낸다 (실제보다 빠르게 보이게)
- 좌우 분할 화면에서 말하는 쪽을 크롭·확대해 보여준다 (전환 컷 대신 줌)
- 자막은 화면 하단, 한 번에 2줄 이내
- 배경음악 없어도 됨. 있다면 아주 낮게
- 마지막 프레임에 정지: `/compare` 축별 표

## 3. 하지 말 것
- "사람이 쓴 것과 구분되지 않습니다" 단언 금지
  → 블라인드 테스트에서 3회 모두 식별됨. Q&A에서 무너진다.
  → 대신 "승인 게이트가 존재하는 이유"로 연결
- 코드·스키마·터미널 화면 노출 금지 (주최측 지침: 사용자 관점)
- 채택 클릭 2회 이상 금지 (무료 API 한도)
