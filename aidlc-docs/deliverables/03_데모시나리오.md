# 데모 영상 시나리오 (1분 40초 목표)

원칙: 코드 설명 없음. 사용자가 무엇을 보고 무엇을 얻는지만. 라이브 API 호출 없음
(모든 화면은 사전 준비된 상태에서 녹화 — /compare는 DB 저장분을 읽으므로 안전).

| 초 | 화면 | 내레이션 (자막) |
|---|---|---|
| 0–15 | 대시보드 상단: 실데이터 지표 + "문의 10건 중 6건 출처 불명" 귀속 막대 | "코드프레소의 실제 6개월 데이터입니다. 문의 10건 중 6건은 어떤 글에서 왔는지 아무도 모릅니다." |
| 15–30 | "다음 주제 후보" — 근거 표시 → **채택하고 초안 생성** 클릭 | "시스템이 데이터로 주제를 제안합니다. '인재 채용 전략', 노출 221회에 순위 20위 — 놓치고 있는 트래픽. 사람은 채택만 합니다." |
| 30–50 | (전환) 폰 화면: 승인 요청 도착 — Voice 점수, **확인 필요 N곳**, 위험 문장 발췌 | "경영진 폰에 도착합니다. 글 전체가 아니라 확인할 지점만 옵니다. 컨펌이 1~4일 걸리던 이유는 결재가 느려서가 아니라 다 읽어야 했기 때문입니다." |
| 50–65 | 폰: ❌반려 → 사유 입력 → 대시보드 "시스템이 배운 규칙"에 그 문장 등장 | "반려하면 그 사유가 규칙이 되어 다음 생성부터 반영됩니다. 같은 지적을 두 번 하지 않습니다." |
| 65–80 | 폰: ✅승인 → 🚀발행 → 추적 링크 생성 / 문의 폼 제출 → 폰에 "문의 도착 — 귀속 확정" | "발행하면 추적 링크가 생기고, 이 글에서 온 문의는 자동으로 이 글에 귀속됩니다." |
| 80–100 | /compare: 좌우 대비 + 축별 표 ("자사 언급 0회 vs 6회") | "같은 모델, 같은 주제입니다. 왼쪽은 일반 프롬프트 — 회사 이름이 한 번도 없습니다. 오른쪽이 이 시스템입니다." |

## 녹화 전 체크리스트

- [ ] learned_constraints 1건 이상 존재
- [ ] /compare에 대비가 선명한 결과 저장돼 있는지 확인 (아니면 재생성)
- [ ] 폰 알림음 켜기 · 방해금지 해제
