# Requirements — marketingbot (Codepresso 콘텐츠 오토메이션)

## Intent (승인됨 — 1A)
코드프레소를 위한 AI 콘텐츠 운영 시스템. 8단계 파이프라인(아이디어→기획→원고→편집→업로드→SNS 확산→성과 취합→데이터 축적)이 사람은 승인만 하는 구조로 돌아가고, Voice Engine이 코드프레소가 직접 쓴 글과 구분 안 되는 초안을 생성하며, Data Flywheel이 성과 데이터를 다음 기획에 되먹임한다.

## 확정 사항
- **언어 (4A):** 한국어 우선 (UI + 콘텐츠)
- **스택:** Next.js + Supabase + Vercel + Claude API (+ Telegram Bot API)
- **방법론:** AWS AI-DLC
- **Telegram Bot:** 부가 기능이 아니라 **승인 게이트 + 데일리 브리핑 채널**로 편입.
  브리프의 "경영진 컨펌 1~4일" 병목을 직접 공격하는 핵심 컴포넌트.
- **친구의 6레이어 아키텍처 채택:** 데이터 소스 → 수집 → 처리 → AI 분석 → Telegram 브리핑 → 다음 콘텐츠 선제안. 이것이 곧 Data Flywheel (단계 ⑦⑧→① 루프).

## 데모 깊이 (2번 — 하이브리드로 확정 제안)
| 단계 | 데모 방식 |
|---|---|
| ① 아이디어 / ② 기획 | **REAL** — 성과 데이터 기반 주제 추천 + 콘텐츠 캘린더 |
| ③ 원고 작성 | **REAL** — Voice Engine (핵심 승부처) |
| ④ 편집 | **LIGHT** — 채널별 포맷 변환(제목/요약/태그)까지만, 이미지·영상 편집 제외 |
| ⑤ 업로드 | **HYBRID** — 자체 데모 블로그에는 실제 발행, 외부 채널은 발행 큐+스케줄까지 |
| ⑥ SNS 확산 | **HYBRID** — LinkedIn 포맷 변환 + 예약까지 실제, API 발행은 스텁 (사유: 아래) |
| ⑦ 성과 취합 | **SEEDED** — 실데이터 접근 불가하므로 현실적 합성 데이터로 Supabase 시드 |
| ⑧ 데이터 축적 | **REAL** — 플라이휠 대시보드 + Telegram 브리핑 |

**⑥ LinkedIn 자동 발행에 대한 기술 판단:** 개인 계정 포스팅은 OAuth(w_member_social)로 가능하나 앱 심사·설정 소요, 회사 페이지 포스팅은 Community Management API 별도 승인 필요 → 1주 해커톤 내 불가. "API 연동 지점까지 설계 완료, 데모에서는 발행 큐로 시연"이 정직하고 방어 가능한 라인.

## 심사 제출물 요구사항 (주최측 공지 반영)
1. 문제 정의 카드 — "___ 때문에 발생하는 ___ 문제" + 숫자/출처 + 미해결 범위 + 성공 정의
2. 설계 요약 — 시스템/사람 경계, 신뢰 요소(판단 로그, 추적성, 승인 게이트, 오류 대응)
3. 데모 영상 1~2분 — 입력→처리→출력, 사용자 관점
4. **Baseline 비교 — 동일 입력을 일반 ChatGPT vs 우리 시스템, 한 화면 비교** ← Voice Engine의 존재 이유를 증명하는 슬롯. 최우선 설계 대상.
발표: 5분 발표 + 5분 Q&A.

## 데이터 구분 (혼동 주의)
- **Voice Corpus** = 코드프레소 블로그 원문 텍스트 (Voice Engine 학습/프롬프트용)
- **Performance Data** = 채널 분석 지표 (플라이휠용) — 첨부 스크린샷은 스키마 레퍼런스로 사용
둘 다 Supabase에 저장하되 별개 테이블.

## Out of Scope (이번에 풀지 않는 것)
- 이미지/썸네일/영상 편집 자동화
- 뉴스레터·유튜브·언론PR 채널
- 외부 채널 실제 API 발행 (설계+큐까지만)
